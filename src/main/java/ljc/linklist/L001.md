L001. 环形链表 (Linked List Cycle) 🎡
题目描述 📋
    
            给你一个链表的头节点 head，判断链表中是否有环。 如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。
            核心物理模型：快慢指针 (Floyd's Cycle-Finding Algorithm) 🏃‍♂️
1. 角色设定

           慢指针 (slow)：每次移动 1 个节点。
        
           快指针 (fast)：每次移动 2 个节点。

   2. 追及逻辑

          相对速度：快指针相对于慢指针的移动速度是 1 步/回合。
    
          必定相遇：在一个环形跑道上，速度快的运动员最终一定会从后面“套圈”速度慢的运动员。当 slow == fast 时，物理地址重合，证明有环存在。
    
          撞墙退出：如果链表无环，快指针会率先到达 null。

效率权衡分析 (Trade-off) 📊

        在面试中，这道题通常有两种解法，它们的优劣对比是核心考点：

        特性	快慢指针法 (本项目采用)	哈希表法 (HashSet)
        时间复杂度	O(n) —— 最多走两遍链表。	O(n) —— 遍历一遍链表。
        空间复杂度	O(1) —— 仅需两个指针变量。	O(n) —— 需要存储所有走过的节点。
        物理隐喻	操场套圈跑步。	在走过的房间门口贴贴纸。
        评价	更高效（省内存）。	更直观，但费内存。
关键点总结 🔑

    初始化：建议快慢指针都从 head 出发，在循环体中先移动再判断相遇。

    边界防守：因为快指针一次跳两步，必须检查 fast != null 且 fast.next != null，否则会引发 NullPointerException。

    禁止瞬移：slow = fast 是物理错误，必须确保 slow = slow.next 才能保持速度差。
